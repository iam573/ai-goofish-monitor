# Mac / iPhone 闲鱼 App 捡漏监控

每天早上自动获取爱玖回收的苹果回收报价，按报价表里的全部苹果机型轮流在已登录的闲鱼 App 里搜索，只读取「新发」结果，筛选指定地区（例如厦门）且挂牌价不超过回收报价加允许议价金额的商品，去重后推送。后台可勾选 Mac 和已连接的 iPhone，默认只使用 Mac。

## 每日流程

```text
① 09:00 起检查报价 ──► ② 生成搜索单元 ──────► ③ 搜索时段内轮流搜索 ──────► ④ 判价、去重、推送
   每 30 分钟一次，        报价表里的全部机型       每款机型只搜索一次，         标题识别机型容量，
   拿到当天报价即停止       按 iPhone 系列分组         结果页依次切换容量筛选       核对地区和价格
```

1. **每日报价**：09:00–12:00 每 30 分钟检查一次苹果无保 / 有保两份报价，当天拿到新图片后就不再下载。图片用 macOS Vision OCR 解析成「机型 + 容量 + 成色 + 价格」，同时识别每个机型右侧的扣费项（无保图的「扣费项」两列；有保图的「颜色差价」「备注扣费」两列），可在后台校正。有保图比无保图多一档「高保充新」，这一档不保存，其余成色按有保图自己的列位置读取。
2. **搜索目标**：不需要手动建任务。系统展示最新报价表里的全部苹果机型，并按系列分组。系列复选框可全选或取消该系列所有机型与容量，例如「iPhone 17 全部机型」；机型复选框同样作用于其全部容量。只启用部分子项时，父级显示半选；点击半选会全选。勾选状态只记在容量这一层，系列和机型的状态由下面的容量推导，所以取消整个系列后仍可单独勾选其中的某个机型或容量。
3. **闲鱼搜索**：在搜索时段内（默认 09:00–23:00），调度器挑一个最久没搜的机型。每款机型只从首页或深链进入一次搜索结果页，然后依次切换启用容量的「筛选 › 存储容量 › 容量 › 确定」并读取「新发」，不重复输入关键词。
4. **判价推送**：边搜边判——Mac 端每翻一屏、iPhone 端每拿到一件候选的链接，就立刻判价、写入运行记录，命中马上推送，不等整款机型搜完。从标题识别机型和容量，查对应的参考成色报价，满足以下条件才推送，同一商品只推送一次：
   - 标题不含排除词（回收、求购、ID锁、配件等）；
   - 地区属于目标城市（看卡片地区；卡片上只有区县名时，App 内区域筛选成功也算）；
   - 标题没写容量时，如果 App 内容量筛选成功，就按筛选的容量判价；
   - `商品挂牌价 ≤ 回收报价 + 允许高出金额`（默认 ¥200；报价 ¥4900 时，¥5100 也可进入推送候选）；
   - 商品价不低于报价的 30%（过低通常是引流或非整机）。

手机端使用两阶段采集：优先从首页第 2 个地区 Tab 搜索；该 Tab、搜索栏左侧和结果页区域均匹配目标城市时跳过区域面板，否则在结果页筛选城市。随后逐个勾选容量、点击「确定」并核对结果页标签，只读取「新发」列表。卡片标题、价格和地区经同一套规则筛出候选，只有候选才打开详情、复制分享链接并取得真实商品 ID。容量筛选成功时，标题未写容量的商品可按本轮容量判价；地区确认成功时，地区未显示的卡片可进入候选，明确显示其他城市的仍跳过。多个勾选设备依次运行，共用商品 ID 去重。手机端暂不提供商品图片。

## 后台

打开 <http://127.0.0.1:8765>。左侧导航分为四页，地址栏会记住当前页（如 `#rules`），刷新后停在原处；界面跟随系统自动切换深色模式。

- **顶部状态条**（每页都有）：报价是否已是今天的、当前规则、搜索状态（下一个机型或暂停原因）、今日命中数。导航上的数字是今日命中件数。
- **命中商品**：满足条件的商品、挂牌价相对回收报价的差额和推送状态。
- **监控规则**：右上角是「采集设备」下拉（可多选 Mac 和 iPhone，显示连接状态和采集顺序）和监控总开关，两者即时生效。下面一句话概括当前规则（用哪些设备、在哪个城市、搜多少机型、怎么判价、什么时段），点其中任意高亮词会跳到对应设置。左侧「监控机型」按系列折叠，可按名称筛选，展开后单独启停机型和容量或立即搜索；右侧「规则设置」分地区 / 判价 / 搜索三页，排除词以标签形式增删，判价页实时显示推送区间示例，搜索页估算每轮耗时；改完点「保存规则」，「撤销」恢复到已保存的值。
- **每日报价**：按系列查看报价。点击任意价格打开估价：可切换无保 / 有保和成色，勾选适用的扣费项（如「电池低于80%」「换屏」），底部实时算出 `估价 = 报价 − 已勾选扣费`；区间项（如 `-200-300`）和「以上」项可在范围内改金额，其他容量专属的扣费项收在「其他容量的扣费项」里，没有金额的说明（如「后盖破当大花收」）列在最下面。估价窗口里的「校正报价」用来修改识别错的价格。
  - 「重新识别原图」会用已下载的当天原图重新识别价格和扣费项，手动校正过的价格保留不变。升级后第一次启动时，也会自动给还没有扣费项的最新报价补做一次识别。
- **运行记录**：左侧是搜索记录列表（可只看有命中 / 有警告 / 失败的），每条显示看到几件、命中几件；点击一条，右侧列出这次搜索看到的每件商品、来自哪个容量筛选、判价结论（命中、价格偏高及高出多少、地区不符、排除词等），命中的排在最前并高亮，可按结论筛选。iPhone 端只给符合条件的商品进详情复制链接，其余列表卡片也会记下来（没有链接，标题不可点），所以「看到」是列表里的全部商品；符合价格但没拿到链接的单独标成「价格符合·无链接」并写明原因，不会推送。服务重启时还没结束的搜索会标记为中断，已读到的商品保留。正在进行的搜索会实时刷新（每 3 秒）：显示当前步骤（如「读取 256G 第 2/4 屏」）和已用时，新读到的商品带高亮出现，命中时右下角弹出提示；查看的是最新一条时，下一次搜索开始后会自动切过去。顶部状态条也会显示正在搜索的机型、步骤和已看 / 命中件数。

## 地区

在「监控规则」里填写城市（例如 `厦门`）。系统做两件事：

1. 优先检查首页底部第二个 Tab。它与目标城市一致时，例如都是「厦门」，直接进入该 Tab 并从首页搜索框搜索，结果页排序栏会显示「厦门」，无需再操作区域面板。第二个 Tab 不一致时，才依次点击「区域 › 福建 › 厦门 › 查看」。
2. 读取每张商品卡片上显示的地区，明确是其他城市或省份的不推送。

## 容量筛选与新发

- 容量筛选点击路径默认 `筛选 > 存储容量 > {容量} > 确定`，`{容量}` 会替换成 `256G`、`1T`；App 里显示 `256GB` 也能匹配。点击器会将容量项限制在「存储容量」面板内，避免误点商品卡片上的同名容量。
- 每款机型只搜索一次，再依次筛选各个启用容量。例如 256G 读取「新发」第一页后继续切换 512G。某一容量筛选失败时跳过该容量，避免把未确认容量的列表用于判价。
- 系统等待排序栏实际出现后只点「新发」，读当前屏并向下翻屏（默认 3 次）读完第一页。固定单轮采集，减少额外按钮切换造成的误点和不稳定。
- 运行记录显示本轮看到的卡片数、曝光数和关联商品数；「新发」按钮找不到时会记录错误，容量及地区路径也会分别记录点击结果。

> 首页地区 Tab 搜索、「新发」点击和容量筛选路径已在真实 Mac App 验证。运行记录会保留每一步的商品数和错误；切换失败时只会推送卡片上能确认属于目标城市的商品。

## 本地启动

需要 macOS、Python 3.10 以上和 Xcode Command Line Tools。首次运行：

```bash
cd app-monitor
cp .env.example .env
uv sync --extra dev
./start.sh
```

- 闲鱼 App 必须已经登录并保持运行；
- 在「系统设置 → 隐私与安全性 → 辅助功能」中允许启动服务的终端读取和操作闲鱼界面；
- 首次搜索时会把 `scripts/ax_snapshot.swift` 编译到 `.runtime/`，之后直接调用编译后的程序。

首次启用 iPhone 前，先安装固定版本的 Appium 和 XCUITest 驱动：

```bash
cd app-monitor
npm ci
APPIUM_HOME="$PWD/.appium" npx appium driver install xcuitest@12.13.3
```

手机需要打开开发者模式、信任本机签名的 WebDriverAgent，并已有可用的 WDA 构建。在 `.env` 中设置 `IOS_WDA_BUNDLE_ID` 和 `IOS_WDA_DERIVED_DATA_PATH`（本机真机验证使用 `usePrebuiltWDA`）。勾选手机后，程序会复用已运行的 Appium 服务；本机 4723 端口没有服务时会启动仓库内安装的 Appium。运行采集前请关闭该手机的 Appium Inspector 会话，避免两个会话争用同一设备。未连接的手机保留勾选，但本轮会记为设备失败，不影响同时勾选的 Mac 或其他手机。

连续 3 次搜索失败（通常是 App 未运行、未登录或没有辅助功能权限）时，搜索会自动暂停 10 分钟。

## 推送配置

在 `.env` 中至少配置一个渠道：

```dotenv
NTFY_TOPIC_URL=https://ntfy.sh/your-topic
BARK_URL=https://api.day.app/your-key
WEBHOOK_URL=https://example.com/your-webhook
WEBHOOK_METHOD=POST
WEBHOOK_HEADERS='{"Authorization":"Bearer your-token"}'
WEBHOOK_CONTENT_TYPE=JSON
WEBHOOK_BODY='{"title":"{{title}}","content":"{{content}}"}'
```

后台右上角可以发送测试推送。未配置渠道时命中记录仍会保存，推送状态显示「未配置推送」。
通知标题为机型和容量（如 `iPhone 17 128G`）。正文前面是商品本身：可点击的商品标题，分行显示挂牌价、回收报价、价差、地区、卖家名字（确认是鱼小铺时在名字后加「（鱼小铺）」），接着是「📱 手机打开 ｜ 💻 网页打开」链接（Mac 端有图片地址时再附首张商品图片）；分隔线下面才是参考价，只有这里用表格：各成色回收价表（判价用的成色加粗，最后一列是另一份报价的同成色价）、扣费项表（每项扣多少、扣完后的回收价，区间写成 `−200～300`，「以上」写成 `−1,500 起`）和报价单上没有金额的说明。ntfy / Bark 用同样顺序的纯文本。`{{title}}` 是通知标题，`{{content}}` 是正文，`{{item_title}}` 可单独引用原商品标题。

iPhone 会在已核对标题和价格的候选详情中读取卖家名称及其右侧的鱼小铺标识；标识是无名图片时只对该标识裁片做本地 OCR。昵称按页面显示保留（包括省略号），未识别的信息显示「未识别」；Mac 当前保留列表采集流程，未取得的卖家信息同样显示「未识别」。

报价检查时间由 `.env` 的 `APP_MONITOR_QUOTE_HOUR` / `APP_MONITOR_QUOTE_MINUTE` 控制（默认 09:00）；其他规则都在后台配置并保存在数据库中。

## 调试点击路径

某一步找不到按钮时，用下面的命令看 App 当前界面上实际有哪些文字，再据此修改后台的点击路径：

```bash
uv run python -m app_monitor.ax_dump "iPhone 15 Pro"                          # 打开搜索后列出所有短文字
uv run python -m app_monitor.ax_dump "iPhone 15 Pro" --path "区域 > 福建 > 厦门"  # 点到这一步再列出
uv run python -m app_monitor.ax_dump --path "筛选"                             # 不重新搜索，在当前页面继续点
```

输出按位置从上到下列出文字和坐标，完整节点保存在 `data/debug/`。

## 调试规则

不经过 App，直接提交商品走一遍判价和推送：

```bash
curl -X POST 'http://127.0.0.1:8765/api/targets/15%20Pro/observations?storage=256&region_applied=true&filter_applied=true' \
  -H 'Content-Type: application/json' \
  -d '[{"item_id":"test-1","title":"iPhone 15 Pro 256G 国行","price":2800,"display_region":"厦门"}]'
```

## 数据与安全

- 业务数据库默认位于 `data/app-monitor.sqlite3`，报价图片保存在 `data/daily-quotes/`；
- Mac 闲鱼曝光 DB 始终使用 SQLite 只读模式；iPhone 端不读取 App 私有容器；
- 不保存可访问性树原文、Cookie、Token、签名或 WUA；
- `.env`、运行数据库、报价图片和 `.runtime/` 均被 Git 忽略。

## 目录

```text
src/app_monitor/
  api.py            后台接口与定时任务（报价检查、每分钟搜索调度）
  rules.py          全局规则、搜索时段、从报价表生成搜索机型
  regions.py        城市 / 省份 / 区县数据，区域点击路径与地区判断
  ax_dump.py        调试工具：列出闲鱼窗口里的按钮文字
  quotes.py         报价下载、OCR 解析（价格与扣费项）、重新识别、报价查询
  collector.py      闲鱼 App 操作：首页地区搜索、深链回退、容量筛选、新发单轮读取、卡片与曝光记录关联
  matching.py       标题识别机型容量、排除词、地区、价格判断（纯函数）
  service.py        监控主流程：挑选到期的机型×容量、搜索、判价、保存命中、推送
  notifications.py  ntfy / Bark / Webhook 推送
  db.py config.py   数据库结构与环境配置
scripts/            macOS Vision OCR 与 Accessibility 辅助脚本
web/                无需构建的单页管理后台
tests/              单元测试与接口测试
docs/               技术设计、报价接口、实测记录
experiments/        早期 Appium/XCUITest 实验
```

旧版本的手动任务表 `monitor_tasks` 和命中表 `matches` 会原样保留在数据库里，但不再使用；新的命中记录在 `deals` 表，搜索记录在 `search_runs` 表。
