# Mac 闲鱼 App 捡漏监控

每天早上自动获取爱玖回收的苹果回收报价，按报价表里的全部苹果机型轮流在已登录的 Mac 版闲鱼里搜索，只读取「新发」结果，筛选指定地区（例如厦门）且挂牌价不超过回收报价加允许议价金额的商品，去重后推送。

## 每日流程

```text
① 09:00 起检查报价 ──► ② 生成搜索单元 ──────► ③ 搜索时段内轮流搜索 ──────► ④ 判价、去重、推送
   每 30 分钟一次，        报价表里的全部机型       每款机型只搜索一次，         标题识别机型容量，
   拿到当天报价即停止       按 iPhone 系列分组         结果页依次切换容量筛选       核对地区和价格
```

1. **每日报价**：09:00–12:00 每 30 分钟检查一次苹果无保 / 有保两份报价，当天拿到新图片后就不再下载。图片用 macOS Vision OCR 解析成「机型 + 容量 + 成色 + 价格」，可在后台校正。
2. **搜索目标**：不需要手动建任务。系统展示最新报价表里的全部苹果机型，并按系列分组。系列复选框可整体启停，例如「iPhone 17 全部机型」；也可以单独启停某款机型或容量。
3. **闲鱼搜索**：在搜索时段内（默认 09:00–23:00），调度器挑一个最久没搜的机型。每款机型只从首页或深链进入一次搜索结果页，然后依次切换启用容量的「筛选 › 存储容量 › 容量 › 确定」并读取「新发」，不重复输入关键词。
4. **判价推送**：从标题识别机型和容量，查对应的参考成色报价，满足以下条件才推送，同一商品只推送一次：
   - 标题不含排除词（回收、求购、ID锁、配件等）；
   - 地区属于目标城市（看卡片地区；卡片上只有区县名时，App 内区域筛选成功也算）；
   - 标题没写容量时，如果 App 内容量筛选成功，就按筛选的容量判价；
   - `商品挂牌价 ≤ 回收报价 + 允许高出金额`（默认 ¥200；报价 ¥4900 时，¥5100 也可进入推送候选）；
   - 商品价不低于报价的 30%（过低通常是引流或非整机）。

## 后台

打开 <http://127.0.0.1:8765>：

- **顶部状态条**：报价是否已是今天的、当前规则、搜索状态（下一个机型或暂停原因）、今日命中数。
- **命中商品**：满足条件的商品、挂牌价相对回收报价的差额和推送状态。
- **监控规则**：地区、参考报价（无保 / 有保）、参考成色、允许高出回收报价的金额、排除词、每轮翻屏次数、搜索时段和间隔；机型列表展示所有报价机型，排序固定为「新发」。系列和机型可整体启停，每个容量标签可单独停用；「搜索」只打开一次该机型搜索，再自动切换容量筛选。
- **每日报价**：按系列查看和校正报价。
- **运行记录**：左侧是搜索记录列表（可只看有命中 / 有警告 / 失败的），每条显示看到几件、命中几件；点击一条，右侧列出这次搜索看到的每件商品、来自哪个容量筛选、判价结论（命中、价格偏高及高出多少、地区不符、排除词等），命中的排在最前并高亮，可按结论筛选。

## 地区

在「监控规则」里填写城市（例如 `厦门`）。系统做两件事：

1. 优先检查首页底部第二个 Tab。它与目标城市一致时，例如都是「厦门」，直接进入该 Tab 并从首页搜索框搜索，结果页排序栏会显示「厦门」，无需再操作区域面板。第二个 Tab 不一致时，才依次点击「区域 › 福建 › 厦门 › 查看」。
2. 读取每张商品卡片上显示的地区，明确是其他城市或省份的不推送。

## 容量筛选与新发

- 容量筛选点击路径默认 `筛选 > 存储容量 > {容量} > 确定`，`{容量}` 会替换成 `256G`、`1T`；App 里显示 `256GB` 也能匹配。点击器会将容量项限制在「存储容量」面板内，避免误点商品卡片上的同名容量。
- 每款机型只搜索一次，再依次筛选各个启用容量。例如 256G 读取「新发」第一页后继续切换 512G。某一容量筛选失败时跳过该容量，避免把未确认容量的列表用于判价。
- 系统等待排序栏实际出现后只点「新发」，读当前屏并向下翻屏（默认 3 次）读完第一页。固定单轮采集，减少额外按钮切换造成的误点和不稳定。
- 运行记录显示本轮看到的卡片数、曝光数和关联商品数；「新发」按钮找不到时会记录错误，容量及地区路径也会分别记录点击结果。

> 首页地区 Tab 搜索、「新发」点击和容量筛选路径已在真实 Mac App 验证。运行记录会保留每一步的商品数和错误；切换失败时只会推送卡片上能确认属于目标城市的商品。

## 本地启动

需要 macOS、Python 3.10 以上和 Xcode Command Line Tools。首次运行：

```bash
cd app-monitor
cp .env.example .env
uv sync --extra dev
./start.sh
```

- 闲鱼 App 必须已经登录并保持运行；
- 在「系统设置 → 隐私与安全性 → 辅助功能」中允许启动服务的终端读取和操作闲鱼界面；
- 首次搜索时会把 `scripts/ax_snapshot.swift` 编译到 `.runtime/`，之后直接调用编译后的程序。

连续 3 次搜索失败（通常是 App 未运行、未登录或没有辅助功能权限）时，搜索会自动暂停 10 分钟。

## 推送配置

在 `.env` 中至少配置一个渠道：

```dotenv
NTFY_TOPIC_URL=https://ntfy.sh/your-topic
BARK_URL=https://api.day.app/your-key
WEBHOOK_URL=https://example.com/your-webhook
WEBHOOK_METHOD=POST
WEBHOOK_HEADERS='{"Authorization":"Bearer your-token"}'
WEBHOOK_CONTENT_TYPE=JSON
WEBHOOK_BODY='{"title":"{{title}}","content":"{{content}}"}'
```

后台右上角可以发送测试推送。未配置渠道时命中记录仍会保存，推送状态显示「未配置推送」。

报价检查时间由 `.env` 的 `APP_MONITOR_QUOTE_HOUR` / `APP_MONITOR_QUOTE_MINUTE` 控制（默认 09:00）；其他规则都在后台配置并保存在数据库中。

## 调试点击路径

某一步找不到按钮时，用下面的命令看 App 当前界面上实际有哪些文字，再据此修改后台的点击路径：

```bash
uv run python -m app_monitor.ax_dump "iPhone 15 Pro"                          # 打开搜索后列出所有短文字
uv run python -m app_monitor.ax_dump "iPhone 15 Pro" --path "区域 > 福建 > 厦门"  # 点到这一步再列出
uv run python -m app_monitor.ax_dump --path "筛选"                             # 不重新搜索，在当前页面继续点
```

输出按位置从上到下列出文字和坐标，完整节点保存在 `data/debug/`。

## 调试规则

不经过 App，直接提交商品走一遍判价和推送：

```bash
curl -X POST 'http://127.0.0.1:8765/api/targets/15%20Pro/observations?storage=256&region_applied=true&filter_applied=true' \
  -H 'Content-Type: application/json' \
  -d '[{"item_id":"test-1","title":"iPhone 15 Pro 256G 国行","price":2800,"display_region":"厦门"}]'
```

## 数据与安全

- 业务数据库默认位于 `data/app-monitor.sqlite3`，报价图片保存在 `data/daily-quotes/`；
- 闲鱼曝光 DB 始终使用 SQLite 只读模式；
- 不保存可访问性树原文、Cookie、Token、签名或 WUA；
- `.env`、运行数据库、报价图片和 `.runtime/` 均被 Git 忽略。

## 目录

```text
src/app_monitor/
  api.py            后台接口与定时任务（报价检查、每分钟搜索调度）
  rules.py          全局规则、搜索时段、从报价表生成搜索机型
  regions.py        城市 / 省份 / 区县数据，区域点击路径与地区判断
  ax_dump.py        调试工具：列出闲鱼窗口里的按钮文字
  quotes.py         报价下载、OCR 解析、报价查询
  collector.py      闲鱼 App 操作：首页地区搜索、深链回退、容量筛选、新发单轮读取、卡片与曝光记录关联
  matching.py       标题识别机型容量、排除词、地区、价格判断（纯函数）
  service.py        监控主流程：挑选到期的机型×容量、搜索、判价、保存命中、推送
  notifications.py  ntfy / Bark / Webhook 推送
  db.py config.py   数据库结构与环境配置
scripts/            macOS Vision OCR 与 Accessibility 辅助脚本
web/                无需构建的单页管理后台
tests/              单元测试与接口测试
docs/               技术设计、报价接口、实测记录
experiments/        早期 Appium/XCUITest 实验
```

旧版本的手动任务表 `monitor_tasks` 和命中表 `matches` 会原样保留在数据库里，但不再使用；新的命中记录在 `deals` 表，搜索记录在 `search_runs` 表。
