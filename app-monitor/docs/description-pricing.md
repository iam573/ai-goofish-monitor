# 描述判价规则

当前产品以 iPhone 采集为唯一运行入口。规则位于“监控规则 → 判价”，判价依据位于“运行记录 → 成色与扣费依据”；不新增独立智能评估页。

## 判价链路

1. 机型搜索一次，在结果页切换容量并确认，优先继承首页地区，核对后跳过重复地区筛选。只采集新发。
2. 列表初筛使用该机型容量、所选报价类别中允许成色的最高回收价，加允许议价金额；不预先锁定某个成色。低价比例和有歧义的关键词留到详情判断。
3. 对候选进详情，核对商品标题与价格，读取可访问描述、商品参数、卖家名称和鱼小铺标识，复制官方分享链接。未取得链接的只记录，不推送。
4. 本地根据关键词判成色，并匹配当日报价的扣费/降档备注。金额只能来自报价记录；模型不能自行估计金额。
5. 只有启用 AI 且配置连接时，才把本地符合或待确认的候选做二次复核；本地明确不符合的不调用模型。
6. 按商品ID去重后通知。待确认默认也通知，明确标识原因；之后升级为明确符合可以再通知一次。旧版本已成功推送的商品不因切换规则重复推送。

## 信息缺省口径

| 描述 | 处理 |
| --- | --- |
| 未说明电池、拆修、水印等 | 默认正常，不扣费，不仅因缺失标待确认；事实中仍保留“未说明”，不会写成100%电池或已证明无拆修 |
| 99新、几乎全新、无明显划痕 | 初判靓机 |
| 99新，同时有轻微划痕 | 具体瑕疵优先，按小花 |
| 无拆修，未说明成色 | 不因此判靓机，成色待确认 |
| 无水印、无拆无修 | 否定描述，不触发相应故障扣费 |
| 图片有水印 | 不当成屏幕水印 |
| 明确电池78% | 按报价中的健康度条件扣费；不能把循环100次当健康度100% |
| 明确换屏，但没有可确定的适用备注 | 待确认，不猜扣多少，也不悄悄按无问题成交价处理 |
| 屏幕水印、碎屏、功能故障、锁机 | 默认不收，可修改明确不收问题配置 |

关键词按最长词组和更具体的瑕疵处理，例如“轻微磕碰”不会同时命中通用“磕碰”而重复降档。不同位置的瑕疵取更差档位。仅根据卖家文字判断，不能证明真实成色。

## 报价与扣费

`推送上限 = 对应成色回收报价 − 适用扣费 + 允许议价金额`

例如靓机报价5200，明确电池78%，当日报价写低于80%扣300，允许议价200：调整后回收价4900，挂牌价5100以内可推送。没写电池则不扣这300，上限为5400。

明确、受支持的备注自动识别，例如电池低于80%、换屏、换电池、颜色差价、后盖破当大花收。不支持的复杂备注在规则中核对后启用；备注文本变更会重新识别，单纯金额更新保留原触发条件。电池互斥分档不累加；触发多个冲突备注时保留候选并标待确认。

扣费为区间时计算回收价上下界：保守端也符合才能明确命中；只有乐观端符合则待确认，超过乐观上限则不推。无明确上限的扣费不声称确定回收价。

## 可选 AI

默认关闭。开启后发送商品标题、描述、参数、页面价格和成色规则，使用兼容 Chat Completions 的接口。Key 保存于本地忽略的 `.env`，业务接口不回传。

每项模型事实必须带原文连续片段；校验电池数字、容量、机型。AI不能抹掉本地明确识别的故障，也不能因电池/拆修未写而改变缺省正常口径。模型调用或校验失败重试一次，仍失败则保留本地结果为待确认，明确标注“AI复核失败”。原文没有读到时记录失败，不推送。

## 推送和复核

普通命中显示机型容量标题、商品标题、挂牌价、成色依据、基础回收价、实际扣费、调整后回收价、议价空间、卖家和官方链接。缺省项以“未说明的电池、拆修等按正常处理，未扣费”解释。待确认加标题前缀和原因，候选回收价上限不表述成确定利润。

运行记录关联当时商品快照、规则、报价、事实和结论；后续重算不改写历史判价。可在该入口修正成色或重新判价。“验证模式”只记录，不发送通知。

Mac 历史实现保留用于回溯，不出现在设备列表、不自动回退；未选择iPhone则暂停搜索。当前验证范围和真机边界见 [validation.md](validation.md) 第21节。
